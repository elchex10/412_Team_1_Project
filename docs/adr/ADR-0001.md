# ADR-0001: Web-Based Medical Heart Rate Calculator Architecture

## Status

Accepted

## Team

Giovanni, Erika, Timothy, and Eric

## Context and Problem Statement

Our team is building a Web-Based Medical Heart Rate Calculator. Users enter basic information like their name, age, and gender. The app checks that information, calculates heart rate values, and shows the results to the user.

The main calculation uses the user's age to find their maximum heart rate with the formula 220 - age. The app also calculates a moderate heart rate zone of 50% to 70% and a vigorous heart rate zone of 70% to 85%. The results show up on a dashboard that gives feedback and includes a medical disclaimer.

We needed an architecture that keeps these jobs organized and is realistic for a small student team to build and maintain during the semester. It also had to work with the tools we already picked for the project, which are Node.js, Python 3.14, GitHub, GitHub Copilot, GitHub Actions, and Microsoft Azure.



## Decision Drivers

- Keep the architecture easy for a small team to understand and manage.
- Keep user input, validation, backend logic, calculations, and result display separate.
- Use Node.js and Python 3.14 as the main development technologies.
- Use Microsoft Azure as the planned hosting environment.
- Use GitHub for source control and team collaboration.
- Use GitHub Actions for automated testing, continuous integration, and deployment.
- Use GitHub Copilot as an AI-assisted development tool, with a human checking its work.
- Keep the core heart rate calculations independent from AI availability.
- Have a clear API contract so the team agrees on how data is sent and returned.
- Have an architecture the team can use as a reference in future sprints.

## Considered Options

- A single application with all functionality combined.
- A microservices architecture with independently deployed services.
- A serverless architecture using cloud-managed functions.
- A layered web application that separates the main responsibilities while keeping the overall system simple.

## Decision Outcome

The team chose a layered web application architecture hosted in Microsoft Azure, supported by GitHub-based CI/CD and AI-assisted development through GitHub Copilot.

The system is split into a web interface, input validation, backend application logic, a heart rate calculation engine, and a results dashboard.
