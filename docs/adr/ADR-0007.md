# ADR-0007: Integrate Automated Security Scanning and CI Quality Gates

**Status:** Proposed

**Date:** 2026-11-13

**Decision-makers:** HCDD 412 Team 1

**Technical Story:** Sprint 4 — Week 12 Team Sprint 4

## Context and Problem Statement

During Sprint 4, the team is improving the Heart Rate Calculator by introducing an interactive heart rate dashboard, automated security scanning, improved automated testing, and security vulnerability assessment.

As the application continues to develop, the team needs a consistent process for identifying software defects, preventing regressions, and detecting security vulnerabilities before changes are merged into the main branch.

The Sprint 4 assignment requires the full automated test suite to pass through the team's CI workflow, a security scan to be integrated into GitHub Actions, and no unaddressed critical or high security findings. Security decisions must also be documented, including accepted risks and their corresponding justifications and mitigations.

The team must determine which security scanning approach to adopt and how automated testing, security scanning, pull request reviews, and vulnerability remediation will be incorporated into the development workflow.

## Decision Drivers

- Maintain application reliability as new features are introduced.
- Run the full automated test suite through GitHub Actions.
- Identify dependency vulnerabilities before code is merged.
- Prevent unaddressed critical and high security findings.
- Generate a security scan report for the Canvas submission.
- Require pull request reviews instead of direct pushes to main.
- Keep the development and security workflow compatible with the existing Node.js application.
- Make security decisions and accepted risks transparent to the entire team.

## Considered Options

1. **Use npm audit with GitHub Actions**
   - Automatically scans the Node.js dependency tree for known vulnerabilities.
   - Works with the existing npm project.
   - Can identify dependency vulnerabilities during CI.
   - Does not provide comprehensive source-code security analysis.

2. **Use GitHub CodeQL**
   - Provides static analysis for identifying potential security vulnerabilities in source code.
   - Integrates with GitHub Actions and GitHub security features.
   - Requires additional workflow configuration and review of its findings.

3. **Rely on manual security reviews**
   - Allows developers to inspect code and dependencies manually.
   - Does not provide consistent automated security scanning.
   - May allow vulnerabilities to go unnoticed before merging.

## Decision Outcome

**Proposed option:** Use npm audit integrated into GitHub Actions as the automated dependency security scanning solution for the Node.js application, alongside the existing automated testing workflow.

The team will use GitHub Actions to execute automated tests and security scanning when changes are proposed through pull requests targeting the main branch.

The team will follow these development and security requirements:

- The automated test suite must pass before changes are merged.
- The security scan must run successfully and generate a report for review.
- Critical and high security findings must be addressed before merging.
- A vulnerability that cannot be resolved must be documented as an accepted risk, including its justification and appropriate mitigation.
- Every pull request must receive a review using the Accept / Modify / Reject checklist.
- Changes must be submitted through pull requests rather than direct pushes to main.
- The team must retain the security scan report for the Sprint 4 Canvas submission.

### Positive Consequences

- Improves application reliability through automated regression testing.
- Helps identify dependency vulnerabilities earlier.
- Creates a consistent CI process for reviewing proposed changes.
- Reduces the likelihood of introducing previously resolved defects.
- Improves accountability and transparency through documented security decisions.
- Provides evidence of automated testing and security scanning for Sprint 4.

### Negative Consequences

- Additional CI workflows may increase the time required to complete pull request checks.
- Security findings may require dependency updates or additional investigation.
- Some vulnerabilities may require documented risk acceptance when an affected dependency cannot be changed.
- Developers must maintain automated tests and review security reports throughout future development.
